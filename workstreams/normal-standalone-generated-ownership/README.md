# Normal standalone generated-data ownership

The original enrollment producer changes two preparation fields after real enrollment; the original dispatcher publishes a six-field local identity object. Those normal side effects previously retained their old managed hashes, so an ordinary update/configure reported UPDATE_CONFLICT even after a fully normal shutdown.

This one core source change recognizes only `.palcraft/standalone/scope.json`, `PalCraft-Dev/player-tools/standalone/mac-runtime-config.json`, and `PalCraft-Dev/bridge/lab-identity.json`. It requires the actual current boot's complete original normal-stop receipt, owner/root/token/native-scope/profile binding, original actor waits, event-file identity and stable Saved/WAL metadata. It neither issues nor finalizes that receipt. No credential is read.

The old bytes must come from a committed original transaction and match the existing managed SHA. Scope admits only the original enrolled preparation bit and the original private-client log path. Mac config admits only its original enrolled preparation bit. Local identity admits exactly the original dispatcher fields, with this boot's real SID/process epoch/world/Pal UID and observed time. Both the initial one-field identity baseline and subsequent committed six-field baselines are supported. No old SID is taken from a release placeholder.

The ordinary `_apply` transaction records and backs up the actual pre-change bytes, writes the normal pending files, commits ownership hashes through the original state ledger, and uses the original undo/rollback on faults. It retains the actual current six-field local identity bytes. The original data producer still prepares the next scope/config normally and must retain the permanent client log field. Every other code, binary and managed-data hash guard is unchanged.

Use the original full CLI through `python3 -B run_frozen_cli.py --tool-source /path/to/original/complete/player-tools update --root /path/to/owned/root --bundle /path/to/new/release.zip`. The wrapper overlays the frozen core plus the unchanged, already-approved permanent-log data producer. It does not copy either source into an installation. The actual ordinary update is performed only by the authorized runtime owner.

Four small synthetic temporary-fixture checks passed: original-conflict reproduction and normal original transaction; second normal boot with a committed six-field baseline; arbitrary data/code, wrong boot and old SID rejection; and fault undo restoring the exact physical bytes and original ledger. The fixture uses the original observeTitle result-dictionary schema. No real credential, saved game, UID/SID/key/grant, native witness, game process or GUI is constructed by these checks. No broad SourceCheck/asset-SHA matrix is rerun.
