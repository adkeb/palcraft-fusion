# Current MC10.10 fresh source build

This entry compiles all 100 public production Java sources. The recorded source chain is MC10.6 full source, six MC10.7 units, three MC10.9 target-centre units, and the MC10.10 PassthroughClient unit. PlayFeedback remains its original public production source. The packaged Fabric version is `0.2.0-integration.10.10-live-owned-performance`.

Run one command with your legally obtained existing dependencies:

```sh
nice -n 19 python3 -B build_mc_10_10.py \
  --jdk /path/to/jdk-home \
  --runtime /path/to/runtime-root \
  --fabric /path/to/fabric-api-0.161.0+26.3.jar \
  --websocket /path/to/Java-WebSocket-1.6.0.jar \
  --input-source /path/to/this-source-tree \
  --output /path/to/new-output.jar
```

`--runtime` supplies the original `client/versions/26.3/26.3.jar` and `client/libraries` hierarchy. The recipe pins cached dependencies by hash; it does not download Minecraft, Fabric, a JDK, or assets. The recorded compiler is JDK 25.0.4.1. Dependency binaries are not included in this source package. The separate WebSocket dependency is a third-party library, not an application/project class source.

The builder accepts no previous mod JAR, project classes, or precompiled-profile directory. It uses a new work directory and compiles the whole project for each of the two historical debug profiles, sequentially with one active JVM processor and Serial GC. Each profile must produce all 168 project classes; 140 `-g` and 28 default-profile classes are selected for the 173-entry runtime archive. All selected project bytes originate in this invocation.

`HISTORICAL-LNT.json` names the original three HostState nested record classes and their exact method/descriptor/line-table mappings. Their original minus-one source-line normalization is retained explicitly; method Code and ABI bytes are not patched. Other classes receive no byte transformation. The two temporary Minecraft interface declarations generated by `FabricCompileInterfaces.java` are compile-only and excluded from the runtime JAR.

The new JAR must match `80490b0d35ca66ec777ff8ba606f63f644bce62cc09cf17b4b9703d990e5edc0`. Existing files are never replaced. Local command evidence is retained in the new `.work` directory and `.build.json` receipt; those logs can contain your paths and should be reviewed before publication. Python/zlib or compiler differences can alter exact bytes, so a failed comparison stays a failed result.

This provides a source build entry. A local Mac build does not establish success in another user's new environment, a full Gradle build, an active game/server, or the full gameplay acceptance scope.
