# Reduce repeated native realm discovery in the original client callback

One original `local_realm.current()` invokes five global `FindAllOf` enumerations and the full owned-save verifier; `validate()` calls current again. The existing callback invokes these paths repeatedly through standalone tick, matching, observer, entity, session and view operations. The one actual timing provided by the runtime owner measured80ms in the same CRT for one full current call; its unchanged engine RealTime is a frame-cached value and cannot establish zero elapsed time. Existing discovery stage reports are around1.6seconds. This evidence identifies repeated sampling as a material cost, not a measured count or attribution of every millisecond.

The two-file candidate retains the original full discovery for initial or changed native context. In a stable original callback it refreshes the controller list once, preserving the sole local controller and remote-connected-peer gates. Other previously verified state/account/manager objects use actual live references and native relationship getters. The original loaded-save, native-process and owned-root permission verifier still executes each frame; a rejection has no cached authority fallback.

The existing client tick supplies a frame boundary. Current, validate, same_world and status can share the proof only inside that callback, while every operation checks live controller, pawn/possession, world, game state, saved UID/account, owned transmitter/component, option/mode, selected world and loaded manager/save relations. Invalid references or changed relations immediately run full discovery and the original verifier. End-frame runs before the original error/reset path and clears frame state. Outside a frame, the original full sampler is preserved. There is no time TTL, timer, extra reader, new service or permanent permission bypass.

Original global GameState/account/manager uniqueness discovery remains on context discovery. The fast path follows the engine-selected live relationships of those verified references; it does not repeatedly enumerate every unrelated object. Controller uniqueness and remote connections are refreshed every frame, including known controller connection changes inside the frame. Authority and the current world/process/root verifier are never replaced with caller flags.
